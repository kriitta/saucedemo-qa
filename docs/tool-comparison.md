# Playwright vs Cypress vs Selenium: บันทึกจากการทดสอบ SauceDemo เดียวกัน

## ขอบเขต
ทดสอบ flow เดียวกันบน saucedemo.com (login, cart, checkout, sort) ด้วยสามเครื่องมือ
บนเครื่องเดียว (macOS, Apple Silicon, Chrome ล่าสุด) จำนวนเคสไม่เท่ากัน:
Playwright 20 เคส (รันบน chromium, firefox, webkit), Cypress 11 เคส, Selenium 11 เคส
เอกสารนี้เป็นบันทึกประสบการณ์จากโปรเจกต์ขนาดเล็ก ไม่ใช่ผลการวัดเชิงเปรียบเทียบอย่างเป็นระบบ

## สิ่งที่เจอจริงระหว่างทำ

| หัวข้อ | Playwright | Cypress | Selenium |
|---|---|---|---|
| การติดตั้ง | `npm init playwright` ตั้งค่าให้ แต่รอบแรกคำสั่งถูกขัดจังหวะ และ config ที่สร้างไม่มี `baseURL` ต้องเพิ่มเอง | ติดตั้งและตั้ง config สั้นๆ ผ่านโดยไม่ติดปัญหา | ติดปัญหามากที่สุด (ดูหัวข้อถัดไป) |
| การรอ element | auto-wait และ assertion ที่ retry เอง | retry อัตโนมัติ | ไม่มี ต้องเขียน wait เอง |
| รูปแบบโค้ด | `await` ทุกบรรทัด | เขียนต่อเป็นสายโซ่ ไม่ต้องมี `await` | `await` + `By.css` + ฟังก์ชันรอที่เขียนเอง ยาวที่สุด |
| ตัวรันเทสต์ | มีในตัว | มีในตัว | ต้องเลือกเอง (ใช้ Mocha) |
| หลาย browser | ตั้งใน config เดียว รันผ่านทั้ง 3 browser | รันเฉพาะค่าเริ่มต้นของ `cypress run` ยังไม่ได้เทียบข้าม browser | รันเฉพาะ Chrome |
| ภาษา | TypeScript | JavaScript | JavaScript (Selenium รองรับภาษาอื่น แต่ยังไม่ได้ลอง) |

## ปัญหาตอนติดตั้ง Selenium (ทั้งหมดเจอจริง)
1. Mocha รุ่นล่าสุดทำงานกับ Node 20.15.1 ไม่ได้ (`ERR_REQUIRE_ESM`) แก้โดยใช้ Mocha 10
2. macOS (Gatekeeper) บล็อก chromedriver ที่ดาวน์โหลดมา ต้องปลดป้ายกักกัน
3. มี chromedriver รุ่นเก่า (126) ค้างใน `/usr/local/bin` ซึ่งถูกเลือกใช้ก่อนตัวที่ตรงกับ Chrome (157)
   จนเกิด `SessionNotCreatedError` แก้โดยย้ายตัวเก่าออก
4. ต้องจัดการเปิด/ปิด browser เองทุกเคส

## ตัวอย่างความต่างในโค้ด: TC-006 (เพิ่มสินค้าแล้ว badge แสดง 1)

Playwright
~~~ts
await page.locator(ADD).click();
await expect(page.locator(BADGE)).toHaveText('1');
~~~

Cypress
~~~js
cy.get(ADD).click();
cy.get('.shopping_cart_badge').should('have.text', '1');
~~~

Selenium
~~~js
await click(driver, ADD);
await waitForText(driver, BADGE, '1'); // ฟังก์ชันที่ต้องเขียนเอง วนรอจนข้อความตรงหรือหมดเวลา
~~~

## บทเรียนที่ได้
- **การไม่มี auto-wait เห็นผลจริง:** TC-001 ของ Selenium ล้ม (นับสินค้าได้ 0 แทน 6) เพราะ
  `findElements` คืนค่าทันทีโดยไม่รอ ส่วนเคสเดียวกันใน Playwright และ Cypress ผ่านทันทีเพราะ retry เอง
- **Automation แก้ข้อมูลในเอกสาร manual ได้:** เทสต์ expected-fail ของ BUG-002 ที่ "ผ่านโดยไม่ควรผ่าน"
  ทำให้พบว่า bug report ฉบับแรกระบุตำแหน่งผิด (หน้า Products ไม่ใช่หน้า Cart) และต้องลด Severity
- เทคนิค `test.fail()` สำหรับบั๊กที่รู้อยู่แล้ว ใช้เฉพาะใน Playwright ยังไม่ได้ลองใน Cypress/Selenium

## ความเห็นเรื่องการเลือกใช้ (จากโปรเจกต์ขนาดเล็กนี้ ไม่ใช่ข้อสรุปทั่วไป)
- โปรเจกต์ใหม่ที่ต้องการเริ่มเร็วและทนต่อจังหวะการโหลด: Playwright หรือ Cypress ตั้งค่าและเขียนง่ายกว่ามาก
- ต้องทดสอบข้ามหลาย browser รวม WebKit ในโค้ดชุดเดียว: Playwright สะดวกที่สุดเท่าที่ลองมา
- Selenium ยังมีเหตุผลให้ใช้เมื่อทีมมีโค้ดหรือทักษะภาษาอื่นอยู่แล้ว (เช่น Java, Python)
  หรือองค์กรใช้อยู่เดิม ซึ่งเป็นเหตุผลที่ยังพบในประกาศงาน ราคาที่ต้องจ่ายคือโค้ดสำหรับรอและการตั้งค่า driver

## ข้อจำกัดของบันทึกนี้
เว็บเดียวขนาดเล็ก เครื่องเดียว จำนวนเคสไม่เท่ากัน ยังไม่ได้วัดความเร็วหรือความเสถียรซ้ำหลายรอบ
ข้อสรุปจึงใช้เป็นความเห็นจากประสบการณ์ตรง ไม่ใช่ผลทดลองที่นำไปอ้างอิงเป็นสถิติได้
